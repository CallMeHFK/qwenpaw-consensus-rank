# 判官退化率配对实验（2026-09-22）

## 要回答的问题

v1.4.4 给评审 prompt 加了一条"输出形态只由规则决定"的优先级条款。它是真降
低了 judge 的退化率（只回单个标识符），还是我拿 n=4 的探针过度外推出来的？

## 设计

| 要素 | 取值 | 为什么 |
|---|---|---|
| 端点 | `glm-5.2` @ SenseNova | 退化就是在它身上先看到的 |
| 块 | 10 个匿名映射 seed（1000–1009） | 映射本身是混淆项，必须两侧共用 |
| 配对 | 同一 seed 先跑 old 再跑 new | 逐对交替，抵消网关时段波动 |
| 参数 | temperature 0.2、max_tokens 4096、timeout 90 | 与生产一致；早先探针用 512 会引入截断混淆 |
| 旧模板 | `git show 19134ce^:backend/tool_impl.py` 直接导入 | 不手抄，避免"我以为的旧版" |
| 主指标 | 票可用（解析出 ≥2 标识符） | 决定这张票能不能进共识 |
| 次指标 | 票完整（全部 4 个） | 决定要不要被"仅完整票"规则剔除 |
| 基础设施失败 | 单独记录，不入任一分母 | 502/TLS 与 prompt 无关 |

## 结果

```
完成配对块数: 10  基础设施失败: old=0 new=0

[票可用]  old 9/10 = 90%   new 8/10 = 80%   不一致对 2:1  符号检验精确 p=1.000
[票完整]  old 9/10 = 90%   new 7/10 = 70%   不一致对 3:1  符号检验精确 p=1.000
```

两个指标都判"无法区分"。点估计还略偏负（old 更好），所以**不能说这条款有收益**。

## 结论

1. **v1.4.4 的 prompt 改法未被证明有效**，先前"4/4 完整排序"是 n=4 过度外推，
   已在 README 的 changelog 里公开收回。
2. **退化是模型的低频随机行为**（合并两侧 17/20 可用 ≈ 15% 退化率），不是某一
   句措辞的后果。
3. **不要再用 prompt 措辞去治它**：要在 80% 功效下分辨 90%→70%，需要约 90 个配
   对块 ≈ 180 次调用；这个端点单次 ~80 s，即约 4 小时机时。投入产出不成比例。
4. **该做的是重试**（v1.4.5 已实现）：单遍解析出 <2 标识符时正向重述格式并重问
   一次。按实测 15% 基线、假设两次独立，票丢失率 15% → 约 2.3%，代价只在失败那
   一次多一个调用。"两次都失败"的分支至今未活体命中，属于推断而非量测。
